The problem

Agents are good at working something out and bad at keeping it. A session traces four services, finds the race condition, and then the context window closes and takes all of it along.

The usual fix is to bolt on memory: embeddings in a vector database. The machine can query them, but you can't read them. When the agent remembers something wrong, there's nothing to open and nothing to fix.

Memory you can't look at isn't yours.

What Mindmaps is

Instead of a hidden index, memory gets a shape. Your agent writes cards and links over MCP. You open the board and see exactly what it knows, then drag, edit or throw things away until the map matches how you think about the problem.

  • You can see all of it. A card is one line until you click it. Then it's a full document with its own board underneath.
  • Recall, not search. Results rank wording, meaning and the links between cards together, so the card next to the answer counts too.
  • Links carry a verb. Blocks, supersedes, explains. The direction of the arrow is part of what you're saying.
  • Old thinking sinks. Superseded cards drop down the results with a mark, but nothing gets deleted.
  • Re-runs converge. Write the same thing twice with a stable key and the second write updates the first.

How it works

Mindmaps is a remote MCP server. Every harness signs in to the same account, so what Claude Code learns at work, Codex on the laptop already knows. There's no API key to paste around:

claude mcp add --transport http mindmaps https://mindmaps.b32n.io/mcp

Mindmaps runs no agents of its own. Your harness is the agent and bills to your own subscription; this side only stores, indexes and ranks. You can revoke any harness from settings without touching the others.

Why it fits b32n

It's the same belief as every other project here, applied to AI: what your tools know about your work should be something you can read, correct and keep.
